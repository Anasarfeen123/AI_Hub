# Careers & Internships

## Explanation

Breaking into AI/ML roles — internships, new-grad positions, or research assistantships — follows a different playbook than general software roles, though it shares the same foundation:

- **Portfolio over credentials** — a few well-documented, end-to-end projects (see [Project Ideas](../projects/index.md)) demonstrate more than a list of completed courses. Reviewers want to see you can frame a problem, handle real data, and evaluate honestly, not just run a tutorial.
- **Role types differ** — "ML Engineer" (building and deploying models, closer to software engineering — see [MLOps](../specializations/mlops.md) and [AI Deployment](../specializations/ai-deployment.md)), "Data Scientist" (analysis, experimentation, business-facing), and "Research Scientist/Engineer" (papers, novel methods, usually requires research experience — see [Research](../research/index.md)) expect different preparation.
- **Interview components** — typically some mix of coding (general data structures/algorithms), ML theory/case studies (e.g. "how would you evaluate this model," "how would you handle imbalanced data" — see [Model Evaluation](../machine-learning/evaluation.md)), and a portfolio/project discussion.
- **Open-source and competitions** — public contributions (GitHub projects, Kaggle competitions — see [Resource Library](../resources/index.md)) function as a verifiable track record when you don't yet have work experience.

## Why it matters

AI/ML hiring moves fast and the bar shifts constantly as the field does, but the underlying signal recruiters and hiring managers look for is stable: can you actually build and evaluate something end-to-end, and can you explain your decisions clearly. Students who only complete courses without ever shipping a full project (data → model → honest evaluation → write-up, per the standard this hub uses throughout) consistently struggle in interviews when asked to go one level deeper than "the model got X% accuracy."

## Learning resources

- [Kaggle](https://www.kaggle.com/competitions) — competitions and public notebooks double as both learning and portfolio material.
- [LinkedIn Learning — Career paths in AI](https://www.linkedin.com/learning/) and company engineering blogs (e.g. major AI labs' blogs) for a sense of what different roles actually do day to day.
- [Chip Huyen's blog](https://huyenchip.com/) — widely-cited, candid writing on ML engineering careers, interviews, and what production ML work actually looks like.
- [Papers With Code](https://paperswithcode.com/) and [arXiv](https://arxiv.org/) (see [Research](../research/index.md)) — following these signals genuine engagement with the field beyond coursework.

## Recommended practice

- Turn your best project from this hub into a portfolio piece: a clean GitHub repo with a README explaining the problem, approach, results, and what you'd do differently.
- Practice explaining a project's model-evaluation choices out loud, as if to an interviewer — "why this metric," "how did you avoid leakage," "what would you try next."
- Contribute to a small open-source ML project or enter a Kaggle competition specifically to have something concrete and verifiable to point to.

## Projects

- **Beginner:** Write up one existing project from this hub as a portfolio-ready README (problem, approach, results, limitations).
- **Intermediate:** Enter a Kaggle competition and document your process, not just your final score — the write-up is often more valuable to a reviewer than the leaderboard rank.
- **Advanced:** Make a substantive contribution (a bug fix, a feature, a benchmark) to an open-source ML project, and be ready to explain the change and why it mattered.
